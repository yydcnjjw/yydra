# Yydra Framework

The language used to distinguish Yydra's application framework from its underlying ecosystem, the products built with it, and the products used to validate it.

## Language

**Yydra Framework**:
An AI-native, opinionated, full-stack application framework that provides reusable application capabilities and engineering constraints while leaving each product's distinguishing rules to its Product Domain.
_Avoid_: starter template, Coding Agent, low-code platform

**Yydra Distribution**:
The versioned release of the Yydra Framework, including its supported Golden Stack, Capabilities, agent-facing knowledge, quality constraints, tooling, and evaluation assets.
_Avoid_: Yydra project, starter template

**Agent-native**:
Designed so that framework interfaces, knowledge, examples, constraints, and evaluation evidence form one coherent contract for both Coding Agents and human developers.
_Avoid_: AI-powered, generated by AI, tied to one Coding Agent

**Baseline Skill**:
A Distribution-owned, exact-release Agent Skill snapshot that gives Coding Agents task-oriented knowledge for working safely in a Product Workspace.
_Avoid_: mutable workspace instruction, client-specific prompt, documentation bundle

**Primary Agent Configuration**:
The complete, identified combination of agent client and scaffold, model, instructions, tools, permissions, and resource limits whose behavior an Eval claim measures.
_Avoid_: model, Coding Agent, agent name

**Agent Eval Campaign**:
A versioned set of comparable independent Eval runs over one sealed task, fixed run configurations, and one grading contract that supports a bounded capability claim.
_Avoid_: benchmark, demo, best run

**Safe Completion**:
An Agent Eval run outcome in which the submitted Product Workspace satisfies every required mechanical and task-specific gate and passes the defined qualitative review without human correction.
_Avoid_: partial pass, successful demo, build success

**Golden Stack Candidate**:
A named, pinned composition of technologies being evaluated against a Yydra Distribution's support and validation gates but not yet promoted as a Golden Stack.
_Avoid_: Golden Stack, supported stack

**Golden Stack**:
A named, versioned composition of technologies that Yydra supports and validates as one product-development path.
_Avoid_: stack template, supported technologies

**Supported Golden Stack Surface**:
The named public interfaces of pinned Golden Stack technologies that a Yydra Distribution permits Product Presentation and Product Adapters to use directly under its validation contract.
_Avoid_: Framework API, Ecosystem Escape Hatch, arbitrary dependency

**H5 Application Surface**:
The browser-delivered interactive application target of a Golden Stack, distinct from a document or content site and from native Android and iOS runtimes.
_Avoid_: H5, website, Web build

**Framework API**:
The stable application-facing contract through which Product Domain code uses mechanisms and reusable semantics owned by the Yydra Framework.
_Avoid_: internal helper, underlying library API

**Public API Contract**:
The machine-readable wire contract that a Product Workspace backend presents to its supported clients, derived from authoritative backend source and used for client generation and conformance checks.
_Avoid_: handwritten OpenAPI document, complete application behavior, deployment contract

**Generated Client**:
A regenerable, non-authored client representation of the Public API Contract that Product Domain code consumes only through a Framework API.
_Avoid_: handwritten SDK, Product Domain client, source of truth

**Framework Core**:
The non-selectable part of a Yydra Distribution that every valid Product Workspace requires to satisfy the Framework's base contract.
_Avoid_: default Capability, common product feature

**Product Workspace**:
An independently maintained product codebase initialized from a Yydra Distribution and owned by its product team thereafter.
_Avoid_: generated project, template output

**Product Server Image**:
A Product Workspace's container image containing its backend server and the matching database migration program, built from the same product revision for independent deployment.
_Avoid_: Yydra Distribution, Product Workspace, development container

**Workspace Origin Record**:
The committed, non-resolving record of the exact Yydra Distribution, template identity, and normalized non-secret inputs that created a Product Workspace.
_Avoid_: dependency lockfile, upgrade manifest, template synchronization state

**Mechanical Quality Contract**:
The historical Yydra Distribution-owned contract of required checks, outcomes, exceptions, and evidence through which a Product Workspace demonstrated conformance to that Distribution. Current Workspaces use environment diagnostics and explicit project validation instead.
_Avoid_: CI pipeline, lint configuration, test suite

**Conformance Evidence**:
The recorded inputs, execution identity, outcomes, logs, and retained artifacts supporting a historical Product Workspace claim under one exact Distribution's Mechanical Quality Contract. Retiring that contract does not expand or rewrite a historical claim.
_Avoid_: universal quality certificate, supply-chain approval, build success

**Reference Product**:
A realistic product that consumes Yydra to test the reuse, development workflow, and quality claims of a Yydra Distribution.
_Avoid_: demo, example app

**Capability**:
A selectable, agent-consumable unit of reusable application behavior together with the knowledge, constraints, and evidence needed to adopt it safely in a Product Workspace. Its identity is semantic and may span packages and runtimes.
_Avoid_: crate, package, infrastructure module, Product Domain

**Capability Presentation**:
A Capability-owned reusable UI and interaction module that presents application semantics through the Supported Golden Stack Surface without owning general UI primitives or product-distinguishing rules.
_Avoid_: UI kit, Product Presentation, Product Domain

**Authentication Capability**:
A selectable Capability that provides identity verification through supported external identity providers and manages product sessions. Product-specific authorization and profile rules remain owned by the product.
_Avoid_: password login, permission management, Product Domain

**Product Account**:
A product-owned identity for a user whose access and resources are scoped to that Product Workspace. An external identity can establish a Product Account without making it a shared account across products.
_Avoid_: GitHub username, email address, shared account center

**Product Session**:
A product-owned, revocable period of authenticated access associated with one Product Account. Its lifetime is separate from the user's login state at an external identity provider or another product.
_Avoid_: GitHub login, provider access token, cross-product session

**Product Domain**:
The product-specific concepts, rules, and state transitions that distinguish one Product Workspace from another and remain expressed as normal source code.
_Avoid_: Capability, infrastructure, application code

**Product Presentation**:
The Product Workspace-owned routes, screens, visual language, accessibility semantics, and interaction flows that present Product Domain behavior through Framework APIs, Capability Presentations, and the Supported Golden Stack Surface.
_Avoid_: Product Domain, Capability Presentation, Framework UI

**Product Adapter**:
A Product Workspace-owned adapter at a real seam that isolates Product Domain code from product-specific external, platform, or ecosystem behavior.
_Avoid_: Product Domain, Capability, wrapper

**Ecosystem Escape Hatch**:
An explicit, Product Workspace-owned use of a Golden Stack ecosystem interface that is neither part of the Framework API nor named in the Supported Golden Stack Surface. It cannot reach Framework internals and does not inherit automatic compatibility or evaluation guarantees.
_Avoid_: Framework API, Supported Golden Stack Surface, Framework internal
